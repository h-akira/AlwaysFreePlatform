# 043 アプリのログは、VM のエージェントが OCI Logging の 1 つのログに送る

- 決めた日: 2026-11-26

## 背景

アプリ（プロジェクトのコンテナ）のログは、VM の中の Docker のログ（json-file、10 MB × 3）にしか無く、VM を作り直すと消えるものとしていた。アプリのデバッグのために、ログを VM の外に残したい。方針は、とにかくシンプルにすること。費用が高い、またはしくみが大きく複雑になるなら見送ってもよい。

この ADR は、「ログは VM の中（消えてよい）」という決定を改める。`afp` の操作のログをバケットに置くことは変えない（置き場所は ADR 045）。

## 決定

- VM の Oracle Cloud Agent の Custom Logs Monitoring のプラグイン（Unified Monitoring Agent）が、Docker のログのファイル（`/var/lib/docker/containers/*/*-json.log`）を読み、OCI Logging に送る。
- 送り先は、ロググループ `loggroup-afp-apps` のログ `log-afp-apps` の 1 つ。**全プロジェクトのログをまとめて送り、プロジェクトごとには分けない**。保存は 30 日。
- どのプロジェクトのログかを見分けるため、`afp install` が Docker の設定（`daemon.json`）の `log-opts` に `labels`（`com.docker.compose.project,com.docker.compose.service`）を書く。各行にプロジェクトとサービスの名前が入る見込み（未確認）。見るときは、検索でプロジェクトの名前で絞る。
- VM の権限は、そのロググループにログを送ることだけを足す。ログを読める人は、全プロジェクトのログを読める。
- アプリの側は、標準出力・標準エラーに出すだけ（今までと同じ）。ファイルに書いたログは送られない。
- VM の中の Docker のログ（10 MB × 3）と `docker logs` は、今のまま残る。

## 理由

- アプリの側に変更が要らない。基盤の側も、Terraform のリソース 3 つ（ロググループ・ログ・エージェントの設定）とポリシー 1 文、Docker の設定 1 行で済む。
- エージェントは OCI のイメージにすでに入っていて、新しい部品を VM に入れなくてよい。
- 費用: Logging の品目は保存だけで、月 10 GB まで 0 円（[references/oci-free-tier.md](../references/oci-free-tier.md) §2）。小さなアプリが数個なら収まる見込み（量は測っていない）。
- プロジェクトごとに分けると、Terraform のリソースとエージェントの設定がプロジェクトの数だけ増える。今の利用者は基盤の管理者だけで、分ける要が無い（ADR 044）。

## 採らなかった案

| 案 | 理由 |
|---|---|
| b. アプリが SDK・API で OCI Logging に送る | 各アプリに SDK と鍵の扱いが要る。コンテナからは VM のメタデータを遮断しているので、VM の権限が使えず、鍵を発行して渡すことになる |
| c. Docker のログのドライバーを journald や fluentd に変える | エージェントは journald を読めない。fluentd（ログを集めて送るためのオープンソースのツール）は、受け手を別に立てる要がある。a より得が無い |
| d. Logging Analytics | 機能は多いが大きく、費用が高い（1 単位で月 372 USD から。価格の API、2026-11-26） |
| a で、プロジェクトごとにロググループを分ける | 持ち主が自分のログだけを読めるようにできるが、しくみがプロジェクトの数だけ増える。要るようになってから考える |
| 見送る（今のまま VM の中だけ） | VM を作り直すとログが消え、デバッグに困る |

## 引き換え

- 全プロジェクトのログが 1 つのログに混ざる。ログを読める人は全プロジェクトのログを読める。違う人のプロジェクトを同居させるのは、まず無理になる（ADR 044）。
- 秘密の情報をログに出すと、VM の外に 30 日残る。
- 未確認: A1 の VM で実際に送れるか（公式文書の記述が割れている）、エージェントが Docker のログのファイルを読めるか、ラベルが各行に入るか、ポリシーの絞り方（ロググループで絞る）が効くか。
- Docker の設定を変えたあとに作ったコンテナにだけ、ラベルが付く見込み（推測）。各プロジェクトを一度デプロイし直す。
