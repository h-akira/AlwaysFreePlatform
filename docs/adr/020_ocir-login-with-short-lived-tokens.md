# 020 OCIR へのログインに auth token を使わない

- 決めた日: 2026-11-14

## 背景

OCIR に `docker login` するには、ふつうはユーザの auth token（期限の無いパスワード）を使う。手元の push にも、VM の pull にも、ログインが要る。

## 決定

- 手元も VM も、使うたびに OCI の資格から OCIR のトークン（3600 秒で切れる）を取り、`BEARER_TOKEN` というユーザ名でログインする（[references/oci-registry.md](../references/oci-registry.md) §2）。
- 手元は管理者の CLI のセッション、VM はインスタンス・プリンシパルを使う。

## 理由

- 期限の無い秘密を作らずに済む。漏れても 1 時間で使えなくなる。
- auth token を Vault に置いて VM に読ませる、手元で一度ログインしておく、という手作業と置き場所が要らない。
- 手元と VM で同じ取り方になる。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 管理者の auth token で手元から 1 回だけログインする | 期限が無い。手元の Docker の資格の置き場所に残り続ける |
| auth token を Vault に置き、VM が読んでログインする | 期限が無い秘密が増える。ユーザに結び付くので、そのユーザを消すと VM が pull できなくなる |

## 引き換え

- このトークンの取り方は、OCIR の公式の文書で手順として確かめられていない。手元と VM で通ったことを根拠にしている。
