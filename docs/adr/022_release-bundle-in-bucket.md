# 022 リリース一式はバケットに置く

- 決めた日: 2026-11-14

## 背景

デプロイには、イメージのほかに、その版の `compose.afp.yaml`（リリース一式）が要る。置き場所は、DevOps のデプロイの作りを確かめてから決めることにしていた。手元からのデプロイを作るときに、置き場所が要った。

## 決定

- リリース一式は、基盤のバケットの `releases/<プロジェクト>/<タグ>/` に置く。
- VM は、デプロイ・戻し・起動し直しのたびに、使う版のものをバケットから取り直す。

## 理由

- VM はすでに、プロジェクトの一覧や今の版をバケットから読んでいる。新しいサービスと権限を足さずに済む。
- 置いた版が残るので、戻しのときも VM を作り直したときも、プロジェクトのリポジトリを読まずに同じ版で動かせる。

## 採らなかった案

| 案 | 理由 |
|---|---|
| OCI の Artifact Registry | サービスと権限が 1 つ増える。中身は小さなファイル 1 つで、版の名前で引ければ足りる |
| VM がプロジェクトのリポジトリから、そのタグのファイルを取る | 非公開のリポジトリを VM が読むための資格が要る |
