# 034 base のスタックには、destroy で消せないものと、外の設定が頼るものを置く

- 決めた日: 2026-11-23

## 背景

ADR 013 で、スタックを 2 つに分けた。base には、Terraform の destroy で消せないもの（コンパートメント・Vault・鍵）だけを置き、消せるものはすべて本体に置くとした。

基盤で公開 DNS のゾーンを持つことにした（ADR 035）。ゾーンは destroy で消せるので、ADR 013 に従えば本体に置くことになる。一方、ゾーンを使うには、親のゾーン（OCI の外の DNS）に、このゾーンのネームサーバーを NS レコードで書く（委任）。作り直したゾーンのネームサーバーが前と同じになるかは確かめていない（未確認）。変われば、本体を作り直すたびに OCI の外で委任を直すことになる。

この ADR は ADR 013 を置き換える。

## 決定

- スタックを 2 つに分けるのは今のまま。
  - base: 次のどちらかに当たるものだけ。
    - Terraform の destroy で消せないもの。コンパートメント・Vault・Vault の鍵。
    - 作り直すと、OCI の外の設定を直す要が出るもの。公開 DNS のゾーン。
  - 本体: それ以外のすべて。消えると困るもの（ダンプを置くバケット・予約済みの IP）も、上に当たらなければ本体に置く。本体の destroy の前にバケットを空にする。
- 本体は、base の資源を名前で探す。スタックの間で値を受け渡す仕組みは作らない。
- 本体のシークレットの名前には、作るたびに変わる接尾辞を付ける。

## 理由

- 本体の作り直しを、OCI の中だけで済ませるため。外の設定の手作業が残ると、作り直せば戻るという方針（VM と本体は作り直せる）が崩れる。
- 基準を「消せない」か「外が頼る」の 2 つに限れば、base は小さく、ほとんど変わらないまま保てる。消えると困るかどうかは、ADR 013 と同じく base に移す理由にしない。
- 予約済みの IP も外（DNS のレコード）から頼られていたが、レコードは本体が作るので（ADR 035）、本体に置いたままでよい。

## 採らなかった案

| 案 | 理由 |
|---|---|
| ゾーンも本体に置く（ADR 013 のまま） | ネームサーバーが変われば、作り直しのたびに親のゾーンの NS を直す手作業が要る |
| ゾーンを Terraform の外で一度だけ作る | 何度流しても同じ結果になるように、自分で書く必要がある |
| 予約済みの IP も base に置く | 外から頼られていたのは DNS のレコードで、それは本体が作り直すので要らない |
