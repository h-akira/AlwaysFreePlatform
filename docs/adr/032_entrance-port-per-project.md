# 032 入口のサービスのポートは、プロジェクトごとに決められる（既定は 8080）

- 決めた日: 2026-11-23

## 背景

入口の Caddy は、プロジェクトのドメインへの要求を、いつも `<プロジェクト>:8080` に送っていた。プロジェクトの約束でも、外から受けるサービスは 8080 番で HTTP を待ち受けることにしていた。

フレームワークや既成のイメージには、それぞれ決まった待ち受けのポート（3000・8000 など）がある。8080 番に固定すると、プロジェクトはアプリの設定かイメージを変えて合わせる必要がある。

## 決定

- プロジェクトの一覧の項目に、入口のサービスが待ち受けるポート `port` を足す。省けば 8080。
- Caddy は、ドメインへの要求を `<プロジェクト>:<port>` に送る。
- `port` は Terraform が `afp.json` に書き、`afp` が読む。

## 理由

- 約束は、コンテナを動かしてもらうのに要る最小限だけにする。ポートを合わせるのはプロジェクトの都合で、基盤が決める理由は無い。
- 一覧の項目にすれば、`afp` は今と同じく `afp.json` だけを見て Caddy の設定を書ける。
- 既定を 8080 にすれば、`port` を書いていない今のプロジェクトはそのまま動く。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 8080 番に固定したまま | プロジェクトがアプリかイメージを基盤に合わせる要がある |
| 一覧の項目で、既定を置かず必ず書く | 多くのプロジェクトで同じ値を書くことになる |
| `compose.afp.yaml` からポートを読む | Caddy の設定がデプロイしたファイルの中身に依存し、VM の作り直しや sync のときに各プロジェクトのファイルを読む要がある |
