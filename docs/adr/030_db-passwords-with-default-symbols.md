# 030 DB のパスワードは、Terraform の既定の記号で作る

- 決めた日: 2026-11-22

## 背景

ADR 011 で、基盤が作る DB のパスワードを、英字・数字と、URL でそのまま使える記号（`-`・`_`・`.`・`~`）だけで作り、記号を必ず含めることにした。プロジェクトが接続の URL に、エスケープせずに埋め込めるようにするためだった。DB の管理者のパスワードも同じ作り方にした。

この ADR は、ADR 011 を置き換える。

MySQL HeatWave の DB を作る API は、管理者のパスワードに特殊文字を 1 つ以上求めるが、`~` を特殊文字として数えない（[references/oci-free-tier.md](../references/oci-free-tier.md) §3）。ADR 011 の作り方では、記号が `~` だけになることがあり、そのとき DB を作れない（`400 InvalidParameter`）。

## 決定

- 基盤が作るパスワード（DB の管理者・プロジェクトの DB・生成のシークレット）は、Terraform の `random_password` の既定の記号で作る。記号の候補は指定しない。
- 記号を必ず 1 つ以上含める（ADR 011 から引き継ぐ）。
- DB の管理者のパスワードも、同じ作り方にする（ADR 011 から引き継ぐ）。
- 接続の URL への配慮はしない。URL に埋め込むプロジェクトは、自分でエスケープする。

## 理由

- MySQL HeatWave ではパスワードの検査（`validate_password`）が効いていて、記号が無いとユーザを作れない。DB を作る API も、管理者のパスワードに特殊文字を求める。
- 既定の記号は、どれも DB を作る API に特殊文字として数えられる。記号が足りずに断られることが無い。
- 記号の候補を指定しないほうが単純。URL の形を使うかはプロジェクトが決めることで、基盤が配慮する理由は小さい。
- 既定の記号に、引用符と `\` は入っていない。`afp` がパスワードを SQL の文字列に入れても壊れない。

## 採らなかった案

| 案 | 理由 |
|---|---|
| ADR 011 の 4 つから `~` を外す | 使える記号を、要るわけでもなく減らす。URL への配慮も残る |
| 作り方は変えず、断られたらパスワードを引き直す | 同じことがまた起こりうる |

## 引き換え

- 生成した値（DB のパスワード・生成のシークレット）に `$`・`#`・`&`・`@` などが入る。接続の URL やシェルに入れるプロジェクトは、自分でエスケープする。
