# 038 git とタグを使うのは、プロジェクトの自動のデプロイだけにする。基盤のコードは手元の中身をそのまま届ける

- 決めた日: 2026-11-24

## 背景

ADR 029 で、プロジェクトの自動のデプロイの合図を `release` ブランチへの push にし、版の名前をそのコミットのタグにした。あわせて、基盤のコードもタグで版を決め、VM がそのタグのコードを公開リポジトリ（GitHub）から取ることにしていた。

そのため、基盤の管理者の操作が git に頼っていた。

- `make plan` は、コミットしていない変更があると断り、HEAD のコミットを送っていた。
- `make apply` は、HEAD の plan かを確かめていた。
- `make platform` は、GitHub に push したタグを指定させていた。
- 自動のデプロイのビルドも、基盤のコードを GitHub から取っていた。

手元からのデプロイは、ADR 037 で git に頼らなくなった。基盤の操作も同じにする。

この ADR は ADR 029 を置き換える（プロジェクトの部分は、そのまま引き継ぐ）。

## 決定

- git とタグに頼るのは、プロジェクトの自動のデプロイだけにする（ADR 029 から引き継ぐ）。
  - 合図は、プロジェクトのリポジトリの `release` ブランチへの push。トリガーの絞りは基盤で固定する。
  - 版の名前は、`release` の先頭のコミットに付いた `v` で始まるタグ。無い、または複数あるときは、ビルドを失敗にする。
  - プロジェクトは、`release` とタグを 1 回の push で送る（`git push --atomic origin HEAD:release <タグ>`）。
  - ビルドのパイプラインのソースの既定のブランチも `release` にする。
  - トリガーの絞りが違えば、`make apply` が、トリガーを作り直さずに絞りだけを直す。
- それ以外の操作は git に頼らず、手元のディレクトリの中身をそのまま使う。コミットしていなくても、git で管理していなくてもよい。
  - `make plan` は、手元の `terraform/` をそのまま送る。plan のジョブには、送った中身のハッシュを名前に付ける。
  - `make apply` は、最新の plan が、今の `terraform/` の中身（ハッシュが同じもの）から作られたときだけ apply する。
  - `make platform` は、VM と自動のデプロイのビルドが使う基盤のコード（`afp/`・`bin/`・`caddy/`・`mysql/`・`scripts/`）を、そのまま `platform.tar.gz` に固めてバケットに置き、VM に入れ替えさせる。
  - VM の起動のスクリプトは、バケットの `platform.tar.gz` を取って入れ替える。GitHub は使わない。
  - 自動のデプロイのビルドも、基盤のスクリプトをバケットの `platform.tar.gz` から取る。
- 基盤のリポジトリのタグは、管理のために任意で付けるもので、デプロイには関係しない。
- 設定（`terraform.tfvars.json`）の置き場所は、ディレクトリとして扱う。git で管理するかは自由。

## 理由

- シンプルさを優先する。基盤の操作に「コミットする・タグを付ける・push する」を挟まない。その場の中身をそのまま出せる。
- 自動のデプロイだけは、GitHub の push を合図にするので、git に頼るほかない。版の名前をタグで付ければ、出した版に名前が付き、どのコミットかが後から分かる（ADR 029 の理由のまま）。
- バケットに置けば、VM も自動のデプロイのビルドも、同じ中身を同じ場所から取れる。GitHub が見えなくても動く。
- 基盤のコードの版を VM の作成時の設定（user_data）に入れると、版を上げるたびに VM が作り直される。バケットに置けば、作り直さずに上げられる（ADR 029 の理由のまま）。
- plan と apply を中身のハッシュで結べば、「plan を見たものと違うものを apply する」ことは、git が無くても防げる。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 今のまま、基盤のコードもタグで決める（ADR 029） | 基盤の操作のたびにコミット・タグ・push が要る |
| 基盤のコードを、タグでなくコミットで指す | git に頼ることは変わらない |
| `make plan` だけ git に頼ったままにする | 基盤の操作の一部だけ git が要ることになり、決まりが二通りになる |

## 引き換え

- 本番で動いている基盤のコードが「どの版か」は、`platform.tar.gz` のハッシュでしか分からない。git のコミットとは結びつかない（タグを付ければ、管理のうえで結びつけられる）。
- VM の起動のスクリプトそのもの（`afp-bootstrap`）は user_data で入るので、変えたときは VM を作り直したときだけ届く。
