# 026 タグの push からのビルドは、VM の上で行い、イメージを OCIR に置く

- 決めた日: 2026-11-15

## 背景

ADR 003 で、ビルドは VM の上でしないと決めた。理由は、E2.1.Micro（1 GB）ではビルドできないことがあり、VM を動かすだけの場所にしておく方が単純だから。ADR 017 で、VM は取れれば A1（arm64・1 OCPU・6 GB）、取れなければ E2.1.Micro（amd64）にした。いまの VM は A1。

S3 で、タグの push から OCI DevOps のビルドの段でビルドすることにしていた。DevOps のビルドの実行環境を調べると、次のとおりだった（2026-11-15。[references/oci-devops.md](../references/oci-devops.md) §3）。

- CPU は x86_64。arm64 を選ぶ指定は無い。
- 手順は root で動き、Podman も root で動く。それでも、arm64 のエミュレーション（qemu）を登録できない（binfmt_misc を mount できず、「operation not permitted」）。arm64 のコンテナは `Exec format error` で動かない。
- そのため、ビルドの途中で arm64 のプログラムを動かすイメージ（`RUN pip install` など）は、DevOps のビルドの段では作れない。

DevOps のデプロイの Shell の段（コンテナ・インスタンスでコマンドを動かす）も、入っている道具に Podman・Docker が無く、arm64 の形を選べるかの記述も無い。

PAYG にしてから（2026-11-08 以降）、A1 は取れなかったことが無い（2026-11-13 に容量の報告を確かめ、2026-11-15 の作り直しでも取れた）。

## 決定

- タグの push からのビルドは、VM の上で行う。ADR 003 の「ビルドは VM の上でしない」を置き換える。
  - DevOps のビルドの段は、プロジェクトのソースを、そのタグのリリース一式としてバケットに置くだけにする。
  - VM の `afp deploy` が、その版のソースを取り、`build:` のあるサービスを VM の CPU の種類のままビルドし、OCIR に push してから入れ替える。
- イメージは今までどおり OCIR に置く。前の版への戻しと、VM の作り直しのあとの起動は、OCIR から pull する（ビルドし直さない）。
- 手元からのデプロイ（`make deploy`）は今までどおり、手元でビルドして OCIR に置く。
- VM を E2.1.Micro に替えることになったら、ビルドの場所をそのときに考え直す（E2.1.Micro は、DevOps のビルドの実行環境と同じ amd64）。

## 理由

- arm64 の VM 向けのイメージを、DevOps の中で作る手段が無い。VM は arm64 なので、エミュレーション無しでビルドできる。
- ほかの案より部品が増えず、費用もかからない。
- 1 台の VM に載せる自前の基盤では、サーバの上でビルドするのはよくある形（Dokku・Coolify など）。CI で 1 回だけ作って多くのマシンに配る利点は、VM が 1 台なので効かない。
- A1 は 6 GB あり、ADR 003 の理由（1 GB ではビルドできないことがある）が当たらない。
- OCIR に置けば、VM が消えても、ビルドし直さずに同じイメージで戻せる（VM はステートレスのまま）。

## 採らなかった案

| 案 | 理由 |
|---|---|
| VM を E2.1.Micro（amd64）にする | 1/8 OCPU・1 GB と非力。ADR 017 で A1 を選んだ理由が残る |
| arm64 のビルド専用の場所（A1 の小さな VM など）を、ビルドのときだけ作る | 部品と手順が増え、作る・消すの待ちがかかる |
| GitHub Actions の arm64 のランナーでビルドする | OCI の外の仕組みと認証が増える。非公開のリポジトリで使えるかも確かでない |
| ビルドの途中で arm64 のプログラムを動かさない Dockerfile を、プロジェクトに求める | プロジェクトの作りを大きく縛る |
| VM でビルドしたイメージを OCIR に置かない | VM を作り直すと、その版をソースから作り直すことになり遅い。同じイメージになる保証も無い |

## 引き換え

- ビルドの間、動いているアプリと VM の CPU・メモリを取り合う。
- ビルドの層のキャッシュが VM のディスクに溜まる。古いものを消す手当てが要る。
- VM に、OCIR へ push する権限を与える。
- VM を E2.1.Micro にしたとき、タグの push からのデプロイが動かないことがある（1 GB でビルドが通らない）。
