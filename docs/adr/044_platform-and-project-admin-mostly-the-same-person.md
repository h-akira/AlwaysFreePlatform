# 044 基盤の管理者とプロジェクトの管理者は、ほぼ同じ人であることを前提にする

- 決めた日: 2026-11-26

## 背景

ADR 002 では、基盤の管理者とプロジェクトの管理者の受け持ちを分け、「同じ人が両方を担ってもよい」とした。文書の論調も、別の人がプロジェクトを載せることがありうる形で書いていた。

アプリのログを全プロジェクトで 1 つのログにまとめると決めた（ADR 043）。これで、ログを読める人は全プロジェクトのログを読める。プロジェクトの間の分離も、もともとコンテナと DB のユーザの分離にとどまる。

この ADR は、ADR 002 の「同じ人が両方を担ってもよい」を、「ほぼ同じ人であることを前提にする」に改める。受け持ちを分けて約束を決めること（ADR 002 の残り）は変えない。

## 決定

- 基盤の管理者とプロジェクトの管理者（アプリの開発者）は、ほぼ同じ人であることを前提にする。違う人のプロジェクトを同じ基盤に同居させることは、まず無理と考える。
- 受け持ちの分け方と約束は、今のまま保つ。同じ人でも、基盤とプロジェクトの境目を約束として扱う。
- 基盤は、プロジェクトの管理者ごとの OCI の権限・ログの読み分けを用意しない。

## 理由

- 前提をはっきりさせると、ログ・権限・監視のしくみを、プロジェクトごとに分けずに済む。仕組みの単純さを優先する。
- 境目を約束として保てば、基盤を変えてもプロジェクトが壊れず、基盤を公開したままプロジェクトを非公開にできる（ADR 002 の理由はそのまま効く）。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 違う人のプロジェクトも載せられるよう、ログ・権限をプロジェクトごとに分ける | ロググループ・エージェントの設定・権限がプロジェクトの数だけ増える。今の利用者は基盤の管理者だけで、要が無い |
| ADR 002 の論調のまま（同じ人でも別の人でもよい） | 実際のしくみ（1 つのログ・弱い分離）と合わず、読み手が違う人の同居ができると誤解する |

## 引き換え

- 他人のプロジェクトを預かる使い方には、向かない。
- 別の人がプロジェクトを載せるときは、その人のログが基盤の管理者（とログを読める人すべて）に見え、ほかのプロジェクトとの分離が弱いことを承知のうえで行う。
