# 042 DB のバックアップは、VM が週 1 回ダンプを取り、28 日残す

- 決めた日: 2026-11-26

## 背景

HeatWave の Always Free の自動バックアップは、保持が 1 日で変えられない（[references/oci-free-tier.md](../references/oci-free-tier.md) §3）。ADR 004 では「基盤が毎日ダンプを取って補う」と決めたが、定期のダンプのしくみは作っていなかった。デプロイの直前のダンプ（`afp deploy`）と、手で取るダンプ（`afp backup`）だけがあり、どちらもバケットに置いたまま消えなかった。

この ADR は、ADR 004 の「基盤が毎日ダンプを取って補う」を置き換える。ADR 004 のほかの決定はそのまま。

## 決定

- VM の systemd の timer（`afp-backup.timer`。`afp install` が置く）が、**週 1 回、毎週日曜 18:00 UTC（日本時間の月曜 3:00）** に、全プロジェクトの `afp backup` を動かす。VM が止まっていて逃した回は、VM が動き出したときに取る（`Persistent`）。
- ダンプは、ダンプのバケット `bucket-afp-dumps`（ADR 045）に `<プロジェクト>/<UTC の時刻>[-before-<版のタグ>].sql.gz` の名前で置く。デプロイの直前のダンプも同じバケットに置く。
- バケットのライフサイクル・ポリシー（Object Storage が決まった日数で消す規則）で、**最終更新から 28 日で消す**。週 1 回なら 4 世代残る。デプロイの直前のダンプも 28 日で消える。
- `afp backup` は、1 つのプロジェクトのダンプが失敗しても残りのプロジェクトを取り、最後に失敗で終わる。
- 全プロジェクトを取ったときだけ、結果を Monitoring のカスタム・メトリクス `afp/backup_ok`（全部取れたら 1、そうでなければ 0）として送る。アラーム `alarm-afp-backup` が 0 で鳴り、通知のトピック `topic-afp-devops`（デプロイの成否のメールと同じ）にメールする。
- HeatWave の自動バックアップ（保持 1 日）は、そのまま使う。
- 戻すときは、ダンプを DB に流し込む（手順は wiki）。

## 理由

- 費用が 0 で、要るしくみは timer・`afp backup` の直し・消す規則・アラーム 1 つで済む。
- 今のデータは小さく、変わる頻度も低い。週 1 回で 4 世代あれば、個人用のアプリには足りると判断した。
- ライフサイクル・ポリシーは「最終更新から N 日」で消す形で、世代の数では指定できない。25 日では新しいダンプの直前に 3 世代しか残らない。28 日なら直前で 4 世代残る。
- 失敗のメールの送り先に今のトピックを使えば、リソースが増えない。
- 「メトリクスが届かない」ことで鳴らすアラームは、届かないことを数える期間が短く（公式文書で最大 3 日。推測を含む）、週 1 回の送信には使えない見込み。そこで、成功と失敗の両方を値で送り、0 で鳴らす形にした。

## 採らなかった案

| 案 | 理由 |
|---|---|
| DB を有料の種類（いちばん小さい `MySQL.2`、2 ECPU・16 GiB）にし、マネージドの自動バックアップを 30 日にする | 自前のコードが要らず最もシンプルだが、月に約 8,750 円（約 56.5 USD。ほとんどが DB 本体の ECPU の料金。Oracle の価格の API で 2026-11-26 に試算）かかる。ほかがほぼ無料のこの基盤で、いちばん大きな費用になる。データは小さく、性能も要らない。その場で種類を変えられる（DB は再起動する）ので、要るようになれば移れる |
| 今のまま（保持 1 日）に、HeatWave の `BackupFailure` のアラームだけ足す | 費用 0 でマネージドだが、1 日より前に戻せない。`MySQL.Free` でこのメトリクスが出るかも未確認 |
| 毎日ダンプを取り、30 日残す（ADR 004 のまま） | 週 1 回で足りると判断した。回数が少ないほど、失敗のメールも置く量も少ない |
| 世代の数で残す（自前で古いものを消す） | 消すコードと、VM に消す権限が要る。ライフサイクル・ポリシーなら VM は置くだけでよい |

## 引き換え

- 最大で 1 週間分の変更を失いうる（1 日以内なら HeatWave の自動バックアップから戻せる）。
- アラームが知らせるのは、`afp backup` が動いて失敗したときだけ。VM が止まっている・timer が動かないといった「動かなかった」ことには気付けない。それは基盤の監視（ADR 007。未実装）で拾う。
- 自前のしくみ（timer・メトリクスを送るコード）を保つ。
