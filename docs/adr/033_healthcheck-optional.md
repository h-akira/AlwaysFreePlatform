# 033 compose の `healthcheck` は任意にする

- 決めた日: 2026-11-23

## 背景

プロジェクトの約束では、`compose.afp.yaml` の各サービスに `healthcheck` を書くことにしていた。デプロイは、全サービスがヘルスチェックに通るのを待ち、通らなければ前の版に戻す。

一方、`afp deploy` は `docker compose up --wait` で待つだけで、`healthcheck` があるかを確かめていない。`healthcheck` の無いサービスは、コンテナが動いていれば待ち終わる。約束とコードが食い違っていた。

## 決定

- `healthcheck` は任意にする。書いたサービスは、ヘルスチェックに通るのを最大 5 分待つ。書いていないサービスは、コンテナが動き出せば待ち終わる。
- どちらでも、待ち終わらなければ前の版に戻す（今のまま）。
- ヘルスチェックで何を確かめるか（どのパスに要求するか、など）はプロジェクトが決める。基盤は決まったパスを求めない。

## 理由

- 約束は、コンテナを動かしてもらうのに要る最小限だけにする。確かめる道を持たないアプリや、起動しただけで十分なサービスもある。
- コードは今のままで、約束をコードに合わせればよい。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 必須のまま、`afp` で `healthcheck` が無ければ断る | 要らないサービスにも書かせることになる |

## 引き換え

- `healthcheck` を書かないサービスは、起動したあとで正しく動かなくても、デプロイは成功になり、前の版に戻らない。
