# 021 OCIR のリポジトリは Terraform で作らず、デプロイが無ければ作る

- 決めた日: 2026-11-14

## 背景

イメージは OCIR に、プロジェクトのサービスごとのリポジトリ（`afp/<プロジェクト>/<サービス>`）として置く。どのサービスをビルドするかは、プロジェクトの `compose.afp.yaml` を読まないと分からない。

## 決定

- OCIR のリポジトリは Terraform で作らない。デプロイが、`compose.afp.yaml` の `build:` のあるサービスを読み、そのリポジトリが無ければ、基盤のコンパートメントに非公開で作る。
- 本体のスタックの destroy では消えない。

## 理由

- Terraform に置くと、プロジェクトがサービスを足すたびに、基盤の管理者がプロジェクトの一覧を直して apply し直すことになる。サービスの構成はプロジェクトが自由に決めるもので、基盤に伝えることにしていない。
- イメージは、VM を作り直したときに、今の版のまま戻すのに使う。本体を destroy しても残るほうが、作り直しが速い。

## 採らなかった案

| 案 | 理由 |
|---|---|
| プロジェクトの一覧にサービスの名前も書き、Terraform で作る | 上の手間。一覧とプロジェクトの compose の二重管理になる |
| 無いリポジトリへの push に任せる | 作られる場所（ルートのコンパートメントとされる。未確認）を、基盤が決められない |

## 引き換え

- プロジェクトを一覧から消しても、リポジトリとイメージは残る。保存の料金がかかりうるので、手で消す。
