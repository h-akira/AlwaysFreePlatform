# 035 基盤が公開 DNS のゾーンを持ち、プロジェクトの名前から払い出す

- 決めた日: 2026-11-23

## 背景

プロジェクトは、一覧の項目 `domain` に自分のドメイン名を書き、その DNS の A レコードを基盤の VM の IP に向けていた。VM の IP は予約済みのものだが、本体のスタックを作り直すと変わる。そのたびに、すべてのプロジェクトで DNS を直す手作業が要った。

基盤は、入口（Caddy）と証明書を受け持っている。名前の解決だけが基盤の外にあった。

## 決定

- 基盤が公開 DNS のゾーンを 1 つ持つ（OCI DNS。変数 `dns_zone`）。ゾーンは base のスタックに置く（ADR 034）。
- 親のゾーンからの委任（NS レコード）は、管理者が最初に一度だけ行う。
- プロジェクトのドメインは `<プロジェクトの名前>.<dns_zone>` に決まる。一覧の項目 `domain` は無くす。
- 本体のスタックが、プロジェクトごとに A レコードを作り、そのプロジェクトの VM の公開 IP に向ける。TTL は 300 秒。
- ほかのドメイン（ゾーンの外の名前）は扱わない。

## 理由

- 本体を作り直しても、`make apply` でレコードが新しい IP に向くので、手作業が要らない。
- 入口・証明書・名前を、同じ責任のもとに置ける。プロジェクトは DNS を用意しなくてよい。
- 名前から決めれば、一覧に書く項目が減り、名前とドメインがずれることも無い。
- 費用は問い合わせの数だけで、ゾーンそのものには料金が無い（2026-11-23 に Oracle の公開の料金表で確かめた。100 万件あたり 0.85 USD）。個人の規模では小さい。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 今のまま、プロジェクトが DNS を持つ | 作り直しのたびに、全プロジェクトの DNS を手で直す |
| ゾーンを基盤が持ち、ほかのドメインも書ける（ほかのドメインはプロジェクトが CNAME で向ける） | 仕組みが二通りになる。今は要らない |
| ワイルドカードのレコード 1 つ（`*.<dns_zone>`） | VM が増えたとき、プロジェクトごとに向け先を変えられない |
| 親のゾーンのサービス（OCI の外）を Terraform から直接操作する | 外のサービスの資格を基盤に持たせることになる |

## 引き換え

- プロジェクトの名前を変えると、ドメインも変わる。
- 問い合わせには、少ないが料金がかかる（Always Free には入っていない）。
