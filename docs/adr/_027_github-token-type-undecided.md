# 027 ADR 025（classic のトークンにする）を取り消し、トークンの種類を未決に戻す

- 決めた日: 2026-11-16

## 背景

ADR 025 で、DevOps が GitHub を読むトークンを classic（`repo`）にした。理由は、fine-grained のトークンでは、接続の検証もビルドでの取得も、DevOps の内部のエラー（500）で失敗し、DevOps が fine-grained を扱えないと判断したため。

そのあと、別の fine-grained のトークンでは、同じ接続で接続の検証もビルドでの取得も通った。原因は分かっていない（[references/oci-devops.md](../references/oci-devops.md) §3）。

## 決定

- ADR 025 を取り消す。「DevOps が fine-grained を扱えない」という判断は、根拠が崩れた。
- トークンの種類（fine-grained か classic か）は、原因が分かるまで決めない。
- 原因の分からないまま、動くトークンを採ることはしない（通った別の fine-grained のトークンを流用する案は、採らなかった）。
- トークンを基盤で 1 本にすること、Vault のシークレットの作り方は、ADR 023 のまま。

## 理由

- 同じ接続で、別の fine-grained のトークンは通る。fine-grained という種類そのものが原因ではない。
- 原因が分からないまま種類を決めると、期限が来て作り直したときに、同じ問題が繰り返されうる。

## 採らなかった案

| 案 | 理由 |
|---|---|
| ADR 025 のまま classic にする | 根拠（fine-grained を扱えない）が誤り。classic はすべての非公開のリポジトリを読み書きできる |
| 通った別の fine-grained のトークンを流用する | 動くが、なぜ動き、ほかのものがなぜ動かないかが分からない |
| Oracle に問い合わせる | 問い合わせる前に、こちらの側の誤りを探す |
