# 039 設定値・生成するシークレット・手で作るシークレットを分け、Terraform が作ったものを上書きしない

- 決めた日: 2026-11-24

## 背景

プロジェクトのシークレットは、一覧の項目で `generate`（Terraform が生成する）か `manual` かを選んでいた。`manual` は、Terraform が仮の値（`CHANGE_ME`）で作り、人があとから本当の値を新しい版として入れ、Terraform はそれを上書きしない、という作りだった。

GitHub のトークン（ADR 023）と webhook の Secret（ADR 024）も同じ作りだった。トークンは人が、webhook の Secret は `make apply` の中のスクリプト（`triggers.py`）が、Terraform の作った仮の値を上書きしていた。

この作りでは、Terraform の設定が実際の値を表さない。IaC の設定を、詳しい設計書として読めなくなる。

この ADR は、ADR 023 と ADR 024 を置き換える（生きている決定は、そのまま引き継ぐ）。

## 決定

- プロジェクトに渡す値を 3 種類に分け、一覧の項目で書き分ける。
  - `env`: 秘密でない設定値。非公開の設定に値をそのまま書く。Vault を通さず、`afp.json` を通して渡す。
  - `generate`: Terraform が生成するシークレット。プロジェクトの JSON のシークレットに入れる（今までの `generate` と同じ）。
  - `secrets`: 外から持ってくる秘密の値。管理者が Vault に手で作り、非公開の設定には `名前: OCID` だけを書く。Terraform は作らない。
  - 名前は 3 種類の間で重ならないこと。
- 手で作るシークレットは、基盤の Vault の、基盤のコンパートメント（`compartment-afp-main`）に作る。VM が読めるのはそこだけ。名前は自由。
- GitHub のトークンも手で作るシークレットにし、変数 `github_token_secret_id` に OCID を書く。リポジトリを伝えたプロジェクトがあるのに、この変数が無ければ、plan で断る。
- トークンは基盤で 1 本にし、fine-grained（リポジトリを選べ、権限を Contents の読み取りだけにできるもの）を使う（ADR 023 から引き継ぐ）。
- トリガーは Terraform で作らず、`make apply` の中の `triggers.py` が作る・消す・絞りを直す。パイプラインは、リポジトリを伝えたプロジェクトにだけ作る（ADR 024 から引き継ぐ）。
- **webhook の Secret は、`triggers.py` がトリガーと一緒に Vault のシークレットとして作り、トリガーを消すときに一緒に消す**。シークレットには、どのプロジェクトのものかをタグ（`afp-webhook=<プロジェクト>`）で付ける。Terraform は持たない。
  - トリガーがあっても、そのプロジェクトの webhook の Secret が無ければ、トリガーを作り直す。
  - Secret は画面・ファイル・ログに出さない。`make apply` は、トリガーの URL と、Secret を写すコマンドを表示する（ADR 024 から引き継ぐ）。
- **Terraform が作ったものを、人やスクリプトがあとから上書きすることはしない**。

## 理由

- IaC の設定は、そこに書いたとおりの状態を表すものにする。上書きを許すと、設定を読んでも実際の値が分からない。
- 秘密でない値まで Vault に入れる要は無い。非公開の設定に書けば、設定を読めば値が分かる。
- 本当の秘密は、Terraform に値を渡すと state にも残る。手で作り、参照（OCID）だけを書けば、値は Vault の中だけにある。
- 手で作るシークレットは Terraform の外なので、本体のスタックを作り直しても残る。作り直しのたびにトークンや API キーを入れ直さずに済む。
- webhook の Secret は、トリガーを作ったときの応答でしか得られない。トリガーを作るスクリプトが、同じときに Secret も作れば、両者の寿命がそろい、上書きも要らない。
- ADR 024 で Vault を判定に使わなかった理由（Terraform が仮の値で作るので常に「ある」になる）は、Terraform が作らなくなったので当たらない。タグの付いたシークレットがあるかで、トリガーに Secret があるかを判定できる。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 今のまま（仮の値で作り、あとから上書き） | IaC の設定が実際の値を表さない |
| 秘密の値も非公開の設定に書き、Terraform が Vault に入れる | 値が Resource Manager の state にも残る。非公開の設定のリポジトリにも残る |
| webhook の Secret を Terraform で作り、スクリプトが上書きする（今まで） | 上書きになる |
| webhook の Secret をシークレットの名前で見分ける | プロジェクトの名前によっては、ほかのシークレットの名前と見分けられない |

## 引き換え

- 手で作るシークレットは、管理者が CLI かコンソールで作る手間が要る。Terraform の plan には出ない。
- 手で作るシークレットは、プロジェクトを外しても消えない。要らなければ管理者が消す。
- 本体を作り直すと、トリガーの URL と webhook の Secret が新しくなり、webhook を登録し直す（今までと同じ）。
