# 031 OCI の資源の名前は `<種類>-afp-<識別子>` にする

- 決めた日: 2026-11-23

## 背景

これまで、基盤の資源の名前は `afp`（バケット・コンパートメント・VCN・Vault など）か `afp-<識別子>`（`afp-db`・`afp-vm`・`afp-devops` など）だった。同じ `afp` や `afp-db` が種類の違う資源に付いていて、名前だけでは何の資源か分からない。`afp` だけの名前は短く、何のためのものかも読み取れない。

## 決定

- 基盤が作る OCI の資源の名前は `<種類>-afp-<識別子>` にする。英小文字・数字・ハイフンだけを使う。
  - `<種類>` は資源の種類を表す決まった語（`bucket`・`vm`・`subnet`・`secret`・`trigger`・`stack` など）。
  - `<識別子>` は必ず付ける。プロジェクトごとのものはプロジェクトの名前、VM ごとのものは VM の名前、役目で分けるものは役目（`db`・`vm`・`devops` など）。1 つしか無いものは `main`。
  - 例: `bucket-afp-main`・`vm-afp-main`・`subnet-afp-db`・`buildpipeline-afp-<プロジェクト>`・`trigger-afp-<プロジェクト>`・`stack-afp-main`。
- OCIR のリポジトリも当てはめる。名前は `repo-afp-<プロジェクト>/<サービス>` にする。プロジェクトの約束（`image: ${AFP_IMAGE_PREFIX}/<名前>:${AFP_TAG}`）は変えず、`AFP_IMAGE_PREFIX` の最後を `repo-afp-<プロジェクト>` にする。
- シークレットの名前の最後に付けている、作るたびに変わる接尾辞は残す（`secret-afp-<プロジェクト>-<接尾辞>` など）。
- 名前に使える文字が英数字だけの資源（Bastion）は、ハイフンを除いた形（`bastionafpmain`）にする。
- OCI の資源でないもの（Docker のネットワーク・compose のプロジェクト・systemd のユニット・VM の中のパス）と、DNS のラベル（`dns_label`・`hostname_label`）は当てはめない。

## 理由

- 種類が名前の頭にあると、コンソールの一覧や CLI の出力、ポリシーの文で、名前だけで何の資源か分かる。
- 識別子を必ず付けると、どの名前も同じ形になる。あとで同じ種類の資源が増えても、前からある名前を変えずに済む。
- OCIR は `<プロジェクト>/<サービス>` の形のまま頭を変えれば、プロジェクトの `compose.afp.yaml` を直さずに済む。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 今の名前（`afp`・`afp-<識別子>`）のまま | 名前から種類が分からない |
| 1 つしか無いものは識別子を省く（`bucket-afp`） | 名前の形がそろわない。何のためのものかが名前から読み取れない |
| OCIR を `repo-afp-<プロジェクト>-<サービス>` にする | プロジェクトの約束の `image:` の形を変えることになり、全プロジェクトの `compose.afp.yaml` を直す要がある |

## 引き換え

- 名前を変えると、本体のスタックは作り直しになる（バケットや Bastion など、名前を変えると置き換わる資源がある）。DB のデータ・バケットの中身・予約済みの IP・トリガーが新しくなる。
- 前の名前の OCIR のリポジトリのイメージは使われなくなる。全プロジェクトのデプロイし直しが要る。
- Resource Manager のスタックは名前で探すので、今あるスタックの名前も変える要がある。
