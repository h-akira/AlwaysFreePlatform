# 041 VM への ssh は Bastion の Managed SSH で、鍵はそのたびに作る

- 決めた日: 2026-11-25

## 背景

VM への ssh（保守のときだけ）は、Bastion のポート転送のセッションで通していた（[references/oci-bastion.md](../references/oci-bastion.md) §4）。

- VM には、非公開の設定の変数 `ssh_public_key` の公開鍵を、VM を作るときに入れていた。鍵を替えるには VM の作り直しが要った。
- `make ssh` は鍵を 2 つ使っていた。Bastion までは、そのたびに作る使い捨ての鍵。VM へは、管理者の自分の鍵（任意の環境変数 `AFP_SSH_KEY` か、各自の ssh の設定）。

DB へのトンネル（`make db-tunnel`）は、もともと、そのたびに鍵を作って捨てている。

## 決定

- `make ssh` は、Bastion の **Managed SSH** のセッションを使う。そのたびに使い捨ての鍵を 1 つ作り、Bastion の手前と VM の両方に使い、終わったら消す。
- VM の Oracle Cloud Agent の Bastion のプラグインを有効にする。
- 変数 `ssh_public_key` と環境変数 `AFP_SSH_KEY` は無くす。VM に固定の鍵を置かない。

## 理由

- 管理者が鍵を用意・管理しなくてよい。鍵を替えるための VM の作り直しも無くなる。
- `make db-tunnel` と同じく「そのたびに鍵を作る」にそろい、説明が 1 つで済む。
- 入れるかを決めるのは OCI の権限（Bastion のセッションを作れるか）になる。今までも、その権限が無ければ入れなかったので、守りの強さはほぼ変わらない。固定の鍵が漏れる心配は無くなる。

## 採らなかった案

| 案 | 理由 |
|---|---|
| 今のまま（ポート転送と固定の鍵） | 鍵を 2 つ扱い、鍵を替えるには VM の作り直しが要る |
| 22 番を管理者の IP に開けて直接 ssh する | 常に開いた入口が残る（ADR 016） |

## 引き換え

- VM の中で Bastion のプラグインが動く。
- Managed SSH で実際に入れるかは、移行のときに確かめる。入れなければ、ポート転送と固定の鍵に戻す。
