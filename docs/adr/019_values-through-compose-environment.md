# 019 コンテナに渡す値は、環境変数のファイルでなく docker compose の環境変数で渡す

- 決めた日: 2026-11-14

## 背景

[006](006_vault-and-metadata.md) で、VM はデプロイのたびに、Vault から読んだシークレットで環境変数のファイルを作ることにしていた。`afp deploy` を作るときに、ファイルを作らずに渡せることが分かった。この ADR は、006 の決定のうち「環境変数のファイルを作る」の部分を置き換える。

## 決定

- `afp` は、基盤が渡す値（`AFP_*`）とプロジェクトのシークレットを、`docker compose` を起動するプロセスの環境変数として渡す。環境変数のファイル（`--env-file`）は作らない。
- `compose.afp.yaml` の中では、どちらでも同じく `${変数}` で使える。

## 理由

- ファイルを作らなければ、消し忘れ・権限の付け忘れが起きない。VM にシークレットのファイルが残らない。
- 環境変数のファイルは、値の引用符や `$` の扱いが compose の解釈に左右される。プロセスの環境変数なら、値はそのまま届く（`'`・`"`・`$` を含む値でテストした）。

## 採らなかった案

| 案 | 理由 |
|---|---|
| tmpfs（`/run`）に 0600 のファイルを作り、`up` のあとに消す | 上の消し忘れとエスケープの問題が残る。値はコンテナの設定にも残るので、ファイルを消しても隠せるものは増えない |

## 引き換え

- 値はコンテナの設定（`docker inspect`）に残る。ファイルでも同じ。VM の root になれる人は読める。
