# 023 DevOps が GitHub を読むトークンは、基盤で 1 本にする

- 決めた日: 2026-11-15

## 背景

OCI DevOps は、GitHub のリポジトリからコードを取るのに、GitHub の Personal Access Token（以下トークン）を使う。トークンは、GitHub のアカウントで作る合い鍵で、読めるリポジトリ・できること・期限を付けられる。DevOps の GitHub への接続は、トークンそのものでなく、トークンを入れた Vault のシークレットを指す（[references/oci-devops.md](../references/oci-devops.md)）。

基盤には複数のプロジェクトが載り、それぞれが自分の GitHub のリポジトリを持つ。

## 決定

- トークンは基盤で 1 本にする。基盤に載せるプロジェクトのリポジトリを、そのトークンの対象にまとめて選ぶ。
- 種類は fine-grained（リポジトリを選べ、権限を Contents の読み取りだけにできるもの）を使う。DevOps の文書の手順は classic（非公開のリポジトリには、すべての非公開のリポジトリの全権限 `repo` が要るとされる）。fine-grained で読めるかは未確認で、だめなら classic にする。
- トークンを入れるシークレットは、本体のスタックに、仮の値で作る。管理者が本当の値を新しい版として入れ、Terraform はその値を上書きしない（プロジェクトの `manual` のシークレットと同じ作り方）。

## 理由

- 基盤のプロジェクトはどれも同じ管理者のもので、トークンの権限は読み取りだけ。プロジェクトごとに分けても、守れるものが少ない。
- トークンには期限があり、切れたら作り直して入れ直す。本数が増えるほど、その手間が増える。
- シークレットを本体に置くのは、ADR 013（destroy で消せるものは本体）による。値を Terraform に渡さないので、state にトークンが残らない。

## 採らなかった案

| 案 | 理由 |
|---|---|
| プロジェクトごとに 1 本 | 期限の入れ替えがプロジェクトの数だけ要る。DevOps の接続もプロジェクトごとに要る |
| classic のトークンから始める | すべての非公開のリポジトリを読み書きできてしまう。fine-grained で足りるなら要らない権限 |
| トークンを Terraform の変数で渡す | state と、スタックの変数に値が残る |
| シークレットを Terraform の外で、手で作る | 作り直しと destroy の対象から外れ、手の作業が増える |

## 引き換え

- 漏れたときは、選んだすべてのリポジトリのコードが読まれる（書き換えはされない）。
- 本体のスタックを作り直すと、シークレットも作り直される。そのたびに、管理者がトークンを入れ直す。
- プロジェクトを足すたびに、トークンの対象にリポジトリを足す（あとから足せるかは未確認）。
