# 03 役割と責任

[01](01_purpose.md) §4 の方針どおり、基盤の管理者とプロジェクトの管理者の受け持ちを分ける。ここで決めた境目が、基盤とプロジェクトの約束になる。

## 1. 二つの役割

| 役割 | 受け持つもの |
|---|---|
| **基盤の管理者**（以下「基盤」） | 共有のもの。VM・入口（Caddy・証明書・DNS）・MySQL HeatWave の DB システム・Vault の仕組み・DevOps の共通部分・Object Storage・レジストリ・ネットワーク・IAM・費用（[02](02_architecture.md) §3） |
| **プロジェクトの管理者**（以下「プロジェクト」） | 自分のプロジェクトの中のもの。アプリ・自分の DB の中身・自分のシークレットの値・自分のアプリの監視 |

ふつうは同じ人が両方を担い、基盤はそれを前提にする。OCI の中の操作（手元からのデプロイ・シークレットの値を入れること・ログを見ること・VM や DB に入ること）は基盤の管理者が行い、基盤はプロジェクトの管理者ごとの OCI の権限を用意しない。別の人がプロジェクトの管理者を担うときは、デプロイには自動のデプロイを使い、ほかは基盤の管理者に頼む。

原則: **基盤は仕組みを用意し、プロジェクトはそれを使う。基盤はプロジェクトの中身（アプリの正しさ・データ）に責任を持たない。プロジェクトは共有のものを直接触らない。**

## 2. 責任の表

| 対象 | 基盤 | プロジェクト |
|---|---|---|
| VM（作成・作り直し・OS の更新） | ◎ | — |
| 入口（Caddy・証明書・振り分け） | ◎ | — |
| 443 を公開するか（全体に開くか、決めた IP からだけか） | ◎ 切り替える（VM ごとに一律。80 は常に開ける。[02](02_architecture.md) §5.4） | 公開が要るかを基盤に伝える。公開されたときは自分のログインで守る |
| ドメインと DNS | ◎ ゾーンを持ち、プロジェクトの名前から払い出す（`<名前>.<ゾーン>`）。レコードを VM の IP に向ける | — |
| ビルドとデプロイの仕組み（DevOps の共通部分・`afp deploy`・失敗時の自動の戻し） | ◎ | 約束のファイルを書き、版のタグを付ける。自動のデプロイを使うなら、自分のリポジトリの `release` に push する。使わないなら、デプロイを基盤の管理者に頼む |
| アプリの動作・不具合 | — | ◎ |
| 失敗したデプロイのあと、前の版に戻すか | 道具（`make rollback`）を用意し、実行する | ◎ 戻すかどうかを決める |
| ログインと、その回数制限 | — | ◎ アプリの中で行う。基盤の入口は持たない |
| HeatWave の DB システム（稼働・定期的に触ること・接続数の全体の上限） | ◎ | — |
| プロジェクトの DB とユーザの作成 | ◎ | — |
| DB の中身（テーブル・マイグレーション・データの正しさ） | — | ◎ |
| MySQL の版が上がったとき | 手元用の版の指定を上げ、知らせる | 自分のアプリをテストし直す |
| DB のバックアップ | ◎ 仕組みを動かす | — |
| DB の復元 | 道具（DB への入口）を用意し、実行する | 戻すかどうか・どの時点に戻すかを決める |
| シークレットの仕組み（Vault・名前の決まり・環境変数への差し込み） | ◎ | — |
| シークレットの値 | 生成できるものは基盤が生成する | 外から持ってくる値（外部の API キーなど）を入れる |
| 基盤の監視（VM・HeatWave が動いているか） | ◎ | — |
| アプリの監視（自分のアプリが使えるか） | — | ◎ 基盤は道具も見本も用意しない |
| 費用 | ◎ 予算とアラート | メモリの上限などの約束を守る |

- 入口や証明書が壊れたことは、基盤の監視では分からない。各プロジェクトのアプリの監視で気付く。
- 基盤の操作（デプロイ・DB の削除・復元）を Web で受け付けることはしない。基盤の操作は、基盤の管理者が手元から OCI の仕組み（Run Command・Bastion）を通して行う。

## 3. 境目

基盤とプロジェクトがやり取りするのは、次のものだけ。

| 向き | もの |
|---|---|
| プロジェクト → 基盤 | プロジェクトの一覧の1項目（名前・リポジトリ（任意）・ポート（任意）・載せる VM・シークレットの名前と作り方）。基盤の非公開の設定に書く |
| プロジェクト → 基盤 | 約束のファイル（コンテナの構成。自動のデプロイを使うなら、ビルドの手順も）。プロジェクトのリポジトリに置く |
| プロジェクト → 基盤 | 自動のデプロイを使うときは、自分のリポジトリの `release` への push（そのコミットに付けた `v` で始まるタグの名前が、デプロイする版の名前になる） |
| 基盤 → プロジェクト | プロジェクトのドメイン（名前から決まる）と、443 を公開しているか |
| 基盤 → プロジェクト | 値（DB の接続先・ドメイン・プロジェクト名・シークレット）。デプロイのたびに、約束のファイルの変数として渡す |
| 基盤 → プロジェクト | 本番の MySQL の版と設定（手元の開発用）。基盤のリポジトリに置く |
| 基盤 → プロジェクト | デプロイの成否、MySQL の版が上がったことの知らせ |
| 基盤 → プロジェクト | 道具（手元からのデプロイ・戻し・DB への入口・ログの確認）。基盤のリポジトリに置く |
