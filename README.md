# AlwaysFreePlatform

個人開発の小さな Web アプリをいくつも、**OCI（Oracle Cloud Infrastructure）の Always Free の枠の中で、少ない VM と 1 つの DB に相乗りさせて動かす** 共通基盤。コマンド名は `afp`。

**使い方は [wiki](../../wiki) にある。** まずはそちらを読む。

- 基盤を立てる・運用する人（基盤の管理者）: [基盤を立てる](../../wiki/Admin-Setup)
- アプリをデプロイする人（プロジェクトの管理者）: [プロジェクトをデプロイする](../../wiki/Project-Owner-Guide)

## 何のためのものか

Always Free の枠は、VM や DB の **個数** で決まっている。アプリごとに VM と DB を 1 組ずつ用意すると、数個で枠を使い切り、しかもほとんどのリソースが遊ぶ。この基盤は、複数のアプリのコンテナを少ない VM に並べ、DB を共有させることで、無料の枠のまま多くのアプリを本番で動かせるようにする。

## どういうものか

- アプリ（以下「プロジェクト」）は、コンテナの構成を書いたファイル `compose.afp.yaml` を 1 つ用意すれば、デプロイできる。
- 基盤が、プロジェクトごとのドメインと HTTPS の証明書、DB とユーザ、秘密の値の受け渡し、デプロイ、DB のバックアップ、ログ、基盤の監視を用意する。
- デプロイは、基盤の管理者のローカルから行うか、プロジェクトのリポジトリの `release` ブランチへの push で自動で行う。
- VM には失って困るものを置かない。VM が消えても、作り直せば元に戻る。
- 基盤はプロジェクトの中身を知らない。基盤は公開し、プロジェクトは非公開のままデプロイできる。

向くのは、個人や少人数で使い、多少止まってもよい Web アプリ。多くのアクセスや高い可用性が要るものには向かない。

## 始め方

1. OCI のアカウントを作り、wiki の [基盤を立てる](../../wiki/Admin-Setup) のとおりに基盤を立てる。
2. サンプルのプロジェクト `afp-example-hello`（このリポジトリと同じ持ち主の、別のリポジトリ）をデプロイして、一通りを確かめる。
3. 自分のアプリに `compose.afp.yaml` を用意して、デプロイする。

> 開発中。週 1 回の DB のダンプの timer は、本番でまだ回っていない。
